# 문제 해결

자주 겪는 증상과 확인할 곳을 모았습니다. 대부분 앞 단계(①~③)의 설정 문제입니다.

**주의사항**

- Lua를 불러왔는데 IDL이 없다 → protos 이름과 같은 <이름>.idl이 Lua와 같은 폴더에 있는지 확인하세요.
- PCAPNG는 로드됐지만 메시지 트리가 비어 있다 → 연결의 IP:Port가 실제 패킷과 같은지, 연결에 IDL이 지정됐는지 확인하세요.
- 메시지 ID나 상세 디코딩이 실패한다 → IDL의 엔디언·PACK_SIZE·헤더 구조를 실제 송신 구조체와 대조하세요.
- 주기성/연속성 탭이 비어 있다 → IDL의 PERIODIC 목록, 실제 발생 횟수(2회 이상), ③ 단계 필터 상태를 확인하세요.
- 스마트 필터가 너무 많이 숨긴다 → 기능을 끄거나 판정 기준 비율을 높이세요.
- 성적서에 "해당 발생 없음"이 나온다 → 지정한 N번째 발생이 실제 발생 횟수보다 크지 않은지 확인하세요.
- 설정 JSON을 다른 PC에서 열었더니 IDL을 못 찾는다 → JSON은 IDL 경로만 저장하므로 IDL 파일도 함께 옮기세요.
- 버튼이 회색으로 눌리지 않는다 → 대부분 "먼저 무언가를 선택/체크해야 하는" 버튼입니다. 장치 편집·장치 삭제·IDL 제거·선택 삭제 계열은 해당 목록에서 행을 먼저 선택(또는 체크)해야 켜지고, 스마트 필터 관련 버튼은 실시간 분석 진행 중에는 항상 꺼져 있습니다.
- 설정 불러오기 후 이전에 등록해 둔 장치·IDL·연결이 사라졌다 → 오작동이 아니라 원래 동작입니다. 설정 불러오기(JSON·Lua 모두)는 기존 내용에 이어붙이는 것이 아니라 장치·IDL·연결을 통째로 교체합니다 — 기존 구성을 남기고 싶다면 불러오기 전에 먼저 설정 저장으로 따로 보관하세요.
- ① 단계에는 장치·IDL이 보이는데 ② 연결 목록이 비어 있다 → endpoints.lua의 protos 항목이 유효한 소켓 키를 2개 이상 갖추지 못했거나(그 프로토콜 전체가 건너뛰어짐), 또는 설정 JSON에 links 배열이 비어 있는 경우입니다 — ② 단계에서 직접 연결을 추가하세요.
- 메시지는 보이는데 IDL 필드가 표시되지 않는다(원시 바이트만 보임) → 그 연결에 IDL이 지정되지 않았거나("(없음)"), protos 이름과 같은 .idl 파일을 자동으로 찾지 못한 경우입니다. ② 단계에서 그 연결의 IDL 콤보를 직접 지정하세요.
- 스마트 필터 버튼(토글·비율 설정 모두)이 눌리지 않는다 → 실시간 분석(라이브 캡처) 진행 중에는 항상 비활성화됩니다. 캡처를 마치고 최종 PCAPNG를 결과 분석 모드로 다시 열면 다시 켤 수 있습니다.
- IDL 트리의 메시지 행을 더블클릭해도 "IDL 메시지 편집" 창이 안 열린다 → IDL 파일 행이나 이미 설정된 규칙 필드 행(3단)을 클릭한 경우입니다 — 2단(Message ID) 행에서 다시 시도하세요. 주기/비주기와 무관하게 모든 메시지에서 열리며(비주기 메시지는 그 창의 "스마트 필터 대상 관리" 탭만 비활성화됨), IDL 트리 우클릭 메뉴는 더 이상 존재하지 않습니다.
- 메시지 식별자 규칙을 적용/저장했는데 ③·④ 단계 화면이 그대로다 → 정상입니다. 규칙은 IDL 트리와 ".das-idl.json"에만 즉시 반영되고, 이미 로드된 PCAPNG 분석 결과는 ③ 시험 분석 설정에서 PCAPNG를 다시 로드해야 바뀝니다 — ①·③ 탭에 뜨는 "재로드 필요" 안내를 확인하세요.
- 식별자 조합이 10개를 초과해 특정 연결에서 적용되지 않는다 → PCAPNG를 다시 로드한 뒤 그 연결의 메시지 행에 "식별자 조합 10개 초과 — 규칙 미적용"으로 표시됩니다. 값이 거의 항상 바뀌는 필드(자유 실행 카운터, 타임스탬프 계열)를 식별자로 골랐을 가능성이 높으므로, 장치/IDL 설정에서 그런 필드를 빼고 몇 가지 값만 반복되는 필드(모드·상태 플래그 등)만 남기세요 — 같은 IDL을 쓰는 다른 연결이 10개 이하라면 그 연결에는 정상 적용된 채로 유지됩니다.
- IDL 트리에 경고 아이콘이 보인다 → 같은 폴더의 ".das-idl.json" 보조 파일에 문제가 있다는 뜻입니다(JSON 문법 오류, 지원하지 않는 버전, 없는 Message ID, 구조체명 불일치, 없는 필드 경로 등) — 행의 툴팁에서 구체적인 원인을 확인하세요. 파일은 자동으로 고쳐지거나 삭제되지 않습니다.
- 우클릭으로 추가한 기준선이 보이지 않거나 지워지지 않는다 → 기준선은 라인 차트 모드에서만 그려지고 반응합니다(박스 플롯 모드에서는 화면에 나타나지 않습니다). 지우려면 그 기준선의 아이콘을 정확히 우클릭해 "기준선 삭제"를 선택하세요 — 빈 곳 우클릭은 새 기준선을 추가할 뿐입니다.
- 성적서 양식을 불러왔더니 오류로 실패한다 → 양식은 장치 이름·IDL 이름·메시지 ID로 현재 프로젝트와 다시 연결되며, 이 중 하나라도 찾지 못하면 일부만 건너뛰지 않고 불러오기 전체가 실패합니다 — 양식을 만들 때와 똑같은 장치·IDL 이름으로 ①· ② 단계를 먼저 맞추세요.
- 실시간 분석에서 쓸 인터페이스가 목록에 없거나 오류가 뜬다 → 네트워크 어댑터 열거 자체가 실패한 경우로, 화면의 빨간 오류 문구를 확인하고 관리자 권한 실행이나 네트워크 어댑터 상태를 점검하세요.
- wpcap.dll/Packet.dll(Npcap) 관련 오류가 뜬다 → 실시간 분석은 Npcap(또는 WinPcap 호환) 드라이버가 설치되어 있어야 동작합니다. Npcap을 설치한 뒤 실행하세요 — 저장된 PCAPNG를 여는 결과 분석 모드는 이 드라이버 없이도 동작합니다.
- PING 검사가 실패로 나온다 → ICMP 응답이 없다는 뜻일 뿐, 그 장치가 UDP/TCP 데이터를 못 보낸다는 뜻은 아닙니다(ICMP를 막아둔 장비일 수 있음). 실제로 트래픽이 오가는지는 캡처를 시작해 수신 여부로 별도 확인하세요.
- 시간선에만 특정 메시지가 안 보인다(③ 필터·스마트 필터는 모두 켜져 있음) → 그 메시지를 보낸 장치의 열 헤더를 우클릭해 "송신 메시지 전시 관리"를 열고 체크가 꺼져 있지 않은지 확인하세요 — 이 설정은 시간선에만 적용되므로 주기성· 연속성 탭에는 원래부터 영향이 없습니다.
- "송신 메시지 전시 관리"에서 켜 둔 표시 상태가 다음에 열었을 때 사라져 있다 → 정상입니다. 이 설정은 파일로 저장되지 않는 임시 상태라 새 PCAPNG를 로드하거나 새 실시간 세션을 시작할 때마다 "전부 표시"로 자동 초기화됩니다.
